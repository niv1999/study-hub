על מבחן התרגול הזה

המבחן השני בסדרה, ברמת ביניים. הוא בנוי בדיוק בפורמט של המרצה (4 שאלות פתוחות × 10 נק׳ ואחריהן 10 שאלות סגורות × 6 נק׳, מספור רציף 1–14), אבל מרכז הכובד שלו הוא יחידות 3–5: מסלול קריאות המערכת בקרנל ו-Partial I/O, שרשרת ה-FD → struct file → Inode, שדות ה-task_struct, סמנטיקת fork/execve, וחוטים מול תהליכים. יש גם טעימה מיחידות 1–2 (errno) ומ-Sockets.

מה שונה כאן ממבחן א׳

  • פחות הגדרות ״יבשות״, יותר קטעי קוד.
  • שתיים מארבע השאלות הפתוחות הן ״האם הקוד תקין? הסבר״.
  • ארבע מהשאלות הסגורות מציגות קטע קוד ושואלות מה הוא עושה.
  • שאלות ״מספריות״: מה קורה ל-f_count אחרי fork, מהו tgid, וכמה הוראות מכונה יש ב-counter++.

ענו קודם על הכול (תשובות חלק א׳ נשמרות בדפדפן), רק אחר כך פתחו ׳הצג תשובת מודל׳ ודרגו את עצמכם 0 / 3 / 5 / 8 / 10; ׳בדקו אותי׳ נועל את חלק ב׳ ומחשב ציון משוקלל. פורמט הבחינה וטקטיקת המענה — ביחידת ההכנה למבחן.

שלוש עצות לפני שמתחילים:

  • בשאלת ״האם הקוד תקין״ — ענו קודם ׳תקין׳/׳לא תקין׳ במפורש, ורק אז הסבירו. המרצה מנקד את ההכרעה בנפרד מההסבר.
  • מוסכמות ההחזרה הן זהב. קריאת מערכת נכשלת ⇒ -1 + errno; read מחזירה 0 ב-EOF; פונקציות pthread מחזירות 0 בהצלחה וקוד שגיאה חיובי בכישלון.
  • הפרידו בין ״מה שמשותף״ ל״מה שפרטי״. זה הציר של חצי מהשאלות כאן: תהליך מול חוט, אב מול בן, f_pos מול fd.

שאלה 1 10 נק׳

תוכנית במרחב המשתמש מבצעת read(fd, buf, 4096) על קובץ פתוח.
תארו את שלבי האלגוריתם שמבצע הקרנל — מרגע הקריאה ועד שהנתונים נמצאים בבאפר של התהליך.

תשובת מודל:

(1) כניסה לקרנל: הוראת ה-syscall מעבירה את המעבד מ-Ring 3 ל-Ring 0, ו-sys_read ממפה את ה-fd דרך current->files אל אובייקט ה-struct file (fdget); fd לא תקין ⇒ -EBADF.
(2) בדיקת f_mode — שהקובץ אכן נפתח לקריאה (אחרת -EBADF).
(3) הפעלת ה-VFS: vfs_read → read_iter, וב-ext4 ל-ext4_file_read_iter.
(4) בדיקת ה-Page Cache: ב-Cache Hit הנתונים כבר ב-RAM ומדלגים על הדיסק; ב-Cache Miss קוראים את הבלוקים מה-SSD (עץ ה-Extents → אובייקט bio → blk-mq/NVMe) אל תוך ה-Page Cache.
(5) copy_to_user מעתיקה מבאפר הקרנל אל הבאפר של התהליך (באפר פגום ⇒ -EFAULT), f_pos מתקדם במספר הבייטים שנקראו בפועל, וחוזרים ל-Ring 3 עם מספר הבייטים — 0 פירושו EOF.

מה בודקים: (1) שהמעבר Ring 3 → Ring 0 ומיפוי ה-fd ל-struct file מופיעים כשלב ראשון; (2) שמוזכרת בדיקת ההרשאה f_mode; (3) שה-VFS וה-Page Cache הם שלבים נפרדים, ושמובחן Hit מול Miss — זה לב התשובה; (4) ש-copy_to_user וקידום f_pos נאמרים במפורש; (5) בונוס: ערך ההחזרה הוא מספר הבייטים שנקראו בפועל (לא בהכרח מה שביקשנו — Partial I/O), ו-0 ב-EOF.

שאלה 2 10 נק׳

מה בדיוק מעתיק הקרנל כאשר תהליך קורא ל-fork(), ומה אינו מועתק?
כיצד מבחין הקוד בין תהליך האב לתהליך הבן?

תשובת מודל:

fork() יוצרת Clone של ה-task_struct: הבן מקבל עותק של מרחב הזיכרון (memory image), עותק של טבלת ה-File Descriptors (fd_array), ואת הקשר מערכת הקבצים (fs — ה-CWD) של האב.
העתקת הזיכרון היא בפועל lazy copy (Copy-On-Write) ולא deep copy — הדפים מועתקים רק כשכותבים אליהם.
מה שאינו מועתק: ה-PID — הבן מקבל PID חדש וייחודי; וגם התוכנית עצמה אינה מוחלפת — רק execve() מוחק את ה-memory image ובונה חדש.
ההבחנה נעשית לפי ערך ההחזרה: 0 לבן, ה-PID של הבן לאב (ו--1 בכישלון) — שני התהליכים ממשיכים מאותה נקודה בקוד.

מה בודקים: (1) שנאמר Clone של ה-task_struct + עותק של מרחב הזיכרון ושל טבלת ה-FDs (שכחת טבלת ה-FDs = חצי תשובה); (2) שנאמר במפורש שה-PID של הבן חדש; (3) שמוזכר Copy-On-Write/lazy copy כמימוש בפועל; (4) ששני ערכי ההחזרה נכונים — 0 לבן, PID לאב; (5) בונוס: מוני ההפניה (f_count) של הקבצים הפתוחים עולים, ולכן בשרת המקבילי כל צד חייב close משלו; ורק execve בונה memory image חדש.

שאלה 3 10 נק׳

במסגרת מטלת תכנות בקורס ״תכנות מערכות״, התבקשו הסטודנטים לפתח תוכנית בשם my_copy.c להעתקת קבצים בלינוקס, תוך שימוש בקריאות מערכת בלבד (open, read, write, close).

לפניך לב לולאת ההעתקה שכתבו סטודנטים.
עליך לקבוע האם הוא תקין פונקציונלית, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

    char buffer[BUFFER_SIZE];
    ssize_t bytes_read;

    while ((bytes_read = read(src_fd, buffer, BUFFER_SIZE)) > 0) {
        write(dst_fd, buffer, bytes_read);
    }

    close(src_fd);
    close(dst_fd);

תשובת מודל:

הקטע אינו תקין פונקציונלית. ערך ההחזרה של write() אינו נבדק כלל.
write עלולה להחזיר -1 (כישלון — למשל הדיסק מלא), או מספר קטן מ-bytes_read — כתיבה חלקית (Partial I/O). בשני המקרים חלק מהנתונים לא ייכתב, קובץ היעד יֵצא פגום, והתוכנית תסתיים ״בהצלחה״ בלי להודיע דבר.
התיקון: לשמור את ערך ההחזרה ולבדוק גם == -1 (ואז perror + יציאה) וגם bytes_written != bytes_read — או לעטוף את write בלולאה שכותבת עד שכל bytes_read הבייטים נכתבו.

מה בודקים: (1) שנקבע במפורש שהקטע אינו תקין; (2) שהשגיאה מזוהה במדויק — אי-בדיקת ערך ההחזרה של write (ולא ״הבאפר קטן מדי״ או ״חסר fsync״); (3) ששני מצבי הכישלון נמנים: -1 וגם כתיבה חלקית; (4) שמוצע תיקון קונקרטי — השוואה ל-bytes_read או לולאת כתיבה. בונוס: לציין שגם שגיאת read נבלעת כאן — -1 אינו > 0, ולכן הלולאה מסתיימת כאילו הגענו ל-EOF, בלי perror.

שאלה 4 10 נק׳

במסגרת תרגיל בקורס ״תכנות מערכות״, התבקשו הסטודנטים לכתוב תוכנית שיוצרת thread נוסף, וכל אחת משתי יחידות הביצוע מדפיסה את המזהים שלה (print_my_ids מדפיסה PID ו-TID).

לפניך קטע קוד שכתבו סטודנטים.
עליך לקבוע האם הוא תקין פונקציונלית, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

void *foo(void *arg)
{
    print_my_ids();
    return NULL;
}

int main(int argc, const char *argv[])
{
    pthread_t my_thread;

    if (pthread_create(&my_thread, NULL, foo, NULL)) {
        return 1;
    }

    printf("Main Thread:");
    print_my_ids();

    return 0;
}

תשובת מודל:

הקטע אינו תקין פונקציונלית. אין בו לא pthread_join ולא sleep, ולכן ה-Main Thread מסיים את main מיד אחרי ההדפסה שלו.
ב-Linux, כשה-Main Thread מסיים את main הוא ״גורר איתו״ את כל התהליך לסגירה — כל החוטים מתים איתו. לכן ייתכן מאוד שהחוט foo לא יספיק לרוץ ולהדפיס כלל, והפלט אינו עקבי בין הרצות (Non-determinism).
התיקון הנכון: pthread_join(my_thread, NULL) לפני ה-return — האב ממתין לסיום החוט. sleep(2), כמו בדוגמת הכיתה, רק מקטין את הסיכוי לבעיה ואינו פתרון אמיתי.

מה בודקים: (1) שנקבע במפורש שהקטע אינו תקין; (2) שהסיבה מדויקת — סיום main מסיים את כל התהליך ואיתו את כל החוטים (ולא ״pthread_create נכשלה״); (3) שנאמר שהתוצאה אינה דטרמיניסטית — לפעמים כן יודפס ולפעמים לא — ולא ״בוודאות לא ידפיס״; (4) שהתיקון המוצע הוא pthread_join (ו-sleep מוזכר לכל היותר כתיקון-עזר). בונוס: לציין שדווקא בדיקת ה-if כאן נכונה, כי pthread_create מחזירה 0 בהצלחה וקוד שגיאה חיובי בכישלון — לא -1 עם errno.

מה לקחת מכאן למבחן

  1. שלוש מוסכמות החזרה — ולא לבלבל ביניהן. קריאת מערכת שנכשלת מחזירה -1 ומעדכנת errno; read מחזירה 0 ב-EOF ומספר חיובי אחרת; פונקציות pthread מחזירות 0 בהצלחה וקוד שגיאה חיובי בכישלון — בלי errno בכלל (שאלות 1, 4, 14).
  2. ״ערך ההחזרה נבדק?״ — זו השאלה הראשונה בכל קטע קוד. הבאג הכי נפוץ בשאלות המרצה אינו לוגיקה שגויה אלא מה שחסר: write שלא נבדקה (Partial I/O), join שלא בוצע, close שלא נקרא (שאלות 3, 4).
  3. מה משותף ומה פרטי — הציר שחוזר בכל יחידה. תהליכי fork: כל אחד עם עותק זיכרון פרטי (Copy-On-Write) אבל עם struct file משותף ומונה f_count; חוטים: code/data/bss/heap משותפים אבל Stack ואוגרים פרטיים (שאלות 5, 6, 7, 9).
  4. fork מעתיק, execve מחליף, clone משתף. שלוש קריאות, שלוש פעולות שונות לגמרי על ה-memory image — וזה בדיוק מה שהמרצה בודק בשאלות 2, 10 ו-12.
  5. לדעת את המספרים בעל פה. 3 הוראות מכונה ב-counter++; fd 3 הוא הראשון הפנוי (0/1/2 תפוסים); 4096 = גודל עמוד ובאפר; 0644 = rw-r--r--; read ב-EOF = 0. שאלות מספריות הן הנקודות הזולות ביותר בבחינה.
  6. אל תפסלו ״אף אחת מהתשובות הנ״ל״ אוטומטית. במבחן הזה היא הופיעה פעם אחת (שאלה 12) ולא הייתה נכונה — אבל בבחינה לדוגמה של המרצה היא כן הייתה. בדקו כל אפשרות לגופה.
