  2. אחר כך — לחשוף ולדרג. בכל שאלה פתוחה יש כפתור ׳הצג תשובת מודל׳ עם תשובה בסגנון המרצה ורשימת ׳מה בודקים׳. דרגו את עצמכם ביושר: 0 / 3 / 5 / 8 / 10.

שאלה 1 10 נק׳

מהו ההבדל בין user mode לבין kernel mode, ומדוע בכלל נדרש מנגנון של קריאות מערכת (System Calls)?

תשובת מודל:

אלו שני מצבי ריצה (privileged levels) של המעבד: kernel mode הוא מצב הרשאה גבוהה (Ring 0, CPL=0) שבו רץ הגרעין, ו-user mode הוא מצב הרשאה נמוכה (Ring 3) שבו רצים תהליכי המשתמש.
הוראות מיוחסות (privileged instructions, כמו HALT) מתבצעות רק במצב גרעין; תהליך משתמש שינסה לבצע אותן — המעבד יסרב וייצור פסיקה שתעצור אותו מיידית.
לכן, כשתהליך זקוק לשירות שדורש גישה לחומרה, נדרש מנגנון קריאת המערכת: זהו המנגנון שבו תהליך מבקש מהגרעין לבצע עבורו שירות (למשל לפתוח קובץ), תוך מעבר מבוקר מ-Ring 3 ל-Ring 0.

מה בודקים: (1) ששני המצבים מזוהים כרמות הרשאה של המעבד — kernel mode = הרשאה גבוהה (Ring 0), user mode = הרשאה נמוכה (Ring 3); (2) שמוזכרת חלוקת ה-ISA להוראות מיוחסות ולא מיוחסות, ושהזיהוי נעשה בשלב פענוח ההוראה (Instruction Decode) — ניסיון לבצע הוראה מיוחסת ב-user mode יוצר פסיקה והתהליך נעצר מיידית; (3) שההגדרה של System Call מופיעה כלשונה — המנגנון שבו תהליך מבקש מהגרעין לבצע שירות עבורו. בונוס: mode bit: 1 = kernel, 0 = user; ההגדרה האופרציונלית של הגרעין — כל הקוד (למעט ה-bootloader) שבעת ביצועו המעבד ב-CPL=0.

שאלה 2 10 נק׳

מה נשמר ברשומת ה-Inode של קובץ, ומה נשמר ברשומת Directory Entry? התייחסו במפורש לשאלה היכן נשמר שם הקובץ.

תשובת מודל:

ה-Inode מחזיק את המטא-דאטה של הקובץ: סוג האובייקט והרשאות (i_mode), בעלים (i_uid/i_gid), גודל (i_size), חותמות זמן, מונה קישורים קשיחים ומיפוי בלוקי הנתונים (i_block / עץ ה-Extents).
ה-Directory Entry נמצא בבלוקי הנתונים של התיקייה המכילה ומקשר שם אל מספר Inode: שדותיו הם inode, rec_len, name_len, file_type ו-name.
שם הקובץ אינו נמצא ב-Inode כלל — הוא נשמר רק ב-Directory Entry. זו הסיבה שאותו קובץ יכול להיות מוכר בכמה שמות (קישורים קשיחים) עם Inode אחד.

מה בודקים: (1) שנמנים לפחות שלושה שדות מטא-דאטה של ה-Inode — הרשאות וסוג, בעלים, גודל, חותמות זמן, מיפוי הבלוקים; (2) שנאמר במפורש שה-Directory Entry הוא זוג ׳שם → מספר Inode׳ ששוכן בבלוקי הנתונים של התיקייה (תיקייה היא קובץ לכל דבר); (3) שנקבע בבירור שהשם אינו ב-Inode. בונוס מדויק: השדות rec_len (המרחק לרשומה הבאה) ו-file_type (חוסך גישה נוספת לטבלת ה-Inodes ב-ls -l), ושה-Inode תופס 256 בייט ב-ext4.

שאלה 3 10 נק׳

במסגרת מטלת תכנות בקורס ״תכנות מערכות״, התבקשו הסטודנטים לפתח תוכנית בשם my_copy.c להעתקת קבצים בלינוקס, תוך שימוש אך ורק ב-System Calls (open, read, write, close).

לפניך קטע קוד שכתבו סטודנטים — פתיחת קובץ היעד.
עליך לקבוע האם הוא תקין פונקציונלית, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

    int dest_fd = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC);
    if (dest_fd == -1) {
        perror("Failed to create destination file");
        close(src_fd);
        exit(EXIT_FAILURE);
    }

תשובת מודל:

הקטע אינו תקין מבחינה פונקציונלית.
הקריאה ל-open() כוללת את הדגל O_CREAT אך חסר בה הארגומנט השלישי, mode (למשל 0644).
החתימה היא int open(const char *pathname, int flags, mode_t mode), וה-mode נדרש בדיוק כאשר הקובץ עשוי להיווצר. בלעדיו הקובץ ייווצר עם ערך הרשאות אקראי (׳זבל׳) שנשאר בזיכרון, ולכן ייתכן שלא תהיה לתוכנית עצמה הרשאת כתיבה אליו.
יתר הקטע תקין: בדיקת == -1, דיווח ב-perror וסגירת קובץ המקור לפני היציאה.

מה בודקים: (1) שנקבע במפורש שהקטע אינו תקין; (2) שהשגיאה מזוהה במדויק — שימוש ב-O_CREAT בלי ארגומנט mode, ושמצוין שה-mode רלוונטי אך ורק כאשר משתמשים ב-O_CREAT; (3) שההסבר מדוע נכון — ההרשאות של הקובץ החדש נקבעות מערך שאינו מוגדר (כפוף גם ל-umask), ולכן התוצאה בלתי צפויה. בונוס: ציון התיקון — open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644), ופירוש 0644 (בעלים קריאה+כתיבה, קבוצה ואחרים קריאה); וכן שהדגלים עצמם נכונים למטלה — O_TRUNC מאפס קובץ יעד קיים. אין ניקוד על ׳באג׳ מומצא כמו ׳חסרה בדיקת argc׳ — הקטע שניתן הוא רק פתיחת היעד.

שאלה 4 10 נק׳

לפניך לולאת ההעתקה שכתבו סטודנטים באותה מטלה (my_copy.c).
עליך לקבוע האם היא תקינה פונקציונלית, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

    ssize_t bytes_read;

    while (1) {
        bytes_read = read(src_fd, buffer, BUFFER_SIZE);
        if (bytes_read == 0) {
            perror("Error reading from source file");
            exit(EXIT_FAILURE);
        }
        write(dest_fd, buffer, bytes_read);
    }

תשובת מודל:

הלולאה אינה תקינה מבחינה פונקציונלית.
הסטודנטים התייחסו לערך ההחזרה 0 כאל שגיאה, בעוד ש-0 הוא סוף הקובץ (EOF) — כלומר סיום תקין של ההעתקה. לכן כל העתקה מוצלחת תסתיים בהודעת שגיאה שקרית וב-exit(EXIT_FAILURE).
במקביל, השגיאה האמיתית כלל אינה נבדקת: read() מחזירה -1 בכישלון, וכאן הערך הזה יועבר כמות בייטים ל-write().
התיקון: while ((bytes_read = read(...)) > 0), ובתוכה בדיקה נפרדת של bytes_read == -1 ושל ערך ההחזרה של write().

מה בודקים: (1) שנקבע במפורש שהקטע אינו תקין; (2) שהשגיאה מזוהה במדויק — read() מחזירה 0 ב-EOF, לא בשגיאה, והשגיאה מסומנת ב--1 (מוסכמת ה--1 + errno); (3) שנאמר מה התוצאה בפועל — הודעת שגיאה ויציאה בכישלון בסוף כל העתקה תקינה, והלולאה לעולם לא מסתיימת כשורה. בונוס: אזכור Partial I/O — read עשויה להחזיר פחות בייטים ממה שהתבקש, ולכן כותבים בדיוק bytes_read בייטים; ואזכור שגם ערך ההחזרה של write() חייב להיבדק (bytes_written != bytes_read).

מה ללמוד מהמבחן הזה

  1. מוסכמת ערכי ההחזרה — בעל פה. כל קריאת מערכת שנכשלת מחזירה -1 והסיבה מגיעה דרך errno (מספר חיובי: 1=EPERM, 2=ENOENT, 13=EACCES, 22=EINVAL). אצל read() יש ערך שלישי שאסור לבלבל: 0 הוא EOF, לא שגיאה — שאלות 4, 7, 9 ו-11 כולן נופלות על זה.
  2. שלושת הארגומנטים של open(). pathname, flags (מסכת ביטים עם |) ו-mode — והאחרון נדרש בדיוק כאשר משתמשים ב-O_CREAT. שכחה שלו היא באג אמיתי, לא קוסמטי: הקובץ ייווצר עם הרשאות שלא ביקשתם.
  3. שם הקובץ אינו ב-Inode. ה-Inode מחזיק מטא-דאטה (סוג והרשאות, בעלים, גודל, חותמות זמן, מיפוי בלוקים) ותופס 256 בייט; השם יושב ב-Directory Entry שבבלוקי הנתונים של התיקייה, ותיקיית השורש היא תמיד Inode 2.
  4. הפרידו בין ספרייה לבין קרנל. fopen/fprintf/fread/fwrite הן glibc ב-user space; open/read/write/close הן קריאות מערכת שחוצות ל-Ring 0. במטלה שדורשת ׳רק System Calls׳ — הבחירה הזו היא ההבדל בין תקין ללא תקין.
  5. דעו מה יושב בכל שדה של ה-task_struct. fs = CWD ושורש; files = טבלת ה-FD; mm = מרחב הזיכרון הווירטואלי; pid/tgid = מזהים. וכן: fork() מחזירה 0 לבן ואת ה-PID לאב.
  6. בשאלת קוד — קודם ׳תקין / לא תקין׳, אחר כך למה. תשובה שאומרת רק ׳יש באג׳ לא מקבלת ניקוד. נסחו במשפט אחד את השגיאה (מה חסר או מה הפוך) ובמשפט שני את הסיבה (איזו מוסכמת קרנל נשברה) — בדיוק כמו בתשובות המרצה בבחינה לדוגמה.
