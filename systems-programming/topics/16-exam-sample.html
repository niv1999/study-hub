שאלה 1 10 נק׳

מהן שתי יחידות הניהול העיקריות המרכיבות את המבנה הפנימי של מערכת הקבצים?

תשובת המרצה:

מערכת הקבצים בנויה משני מרכיבי ליבה: Inodes (המכילים את המטא-דאטה של הקבצים) ו-Data Blocks (המכילים את תוכן הקבצים עצמו).

מה בודקים: (1) ששמות שתי היחידות מופיעים במפורש — Inodes ו-Data Blocks; (2) שה-Inode מחזיק מטא-דאטה (סוג הקובץ והרשאות, בעלים, גודל, חותמות זמן, מיפוי הבלוקים) — לא את התוכן ולא את השם; (3) שה-Data Block מחזיק את תוכן הקובץ עצמו על ה-NVM.

שאלה 2 10 נק׳

מהו ההבדל הבסיסי ביותר בין Process לבין Thread מבחינת מרחב הכתובות?

תשובת המרצה:

תהליך (Process) מחזיק במרחב כתובות וירטואלי פרטי ומבודד.
לעומתו Thread חולק את מרחב הכתובות של התהליך עם Threads אחרים באותו תהליך.

מה בודקים: (1) שנאמר במפורש שלתהליך מרחב כתובות וירטואלי פרטי ומבודד; (2) שנאמר במפורש שחוטים חולקים את מרחב הכתובות של התהליך שלהם (קוד, נתונים, Heap וקבצים פתוחים); (3) בונוס מדויק — למרות השיתוף, לכל חוט Stack ואוגרים (registers) משלו, ולכן אין הגנה בין חוטים באותו תהליך.

במסגרת מטלת תכנות בקורס ״תכנות מערכות״, התבקשו הסטודנטים לפתח תוכנית בשם my_copy.c להעתקת קבצים בלינוקס.
על התוכנית להשתמש אך ורק ב-System Calls (כגון open, read, write, close), ואסור לה להשתמש בפונקציות מהספרייה הסטנדרטית (כגון fopen או printf) לצורך עבודה עם קבצים.

לפניך קטע קוד שכתבו סטודנטים כחלק מהפתרון.
עליך לקבוע האם הוא תקין פונקציונלית בהתאם לדרישות המטלה, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

    int src_fd = open(argv[1], O_RDONLY);
    if (src_fd == -1) {
        print_error("Cannot open source file or file does not exist.", 46);
        exit(1);
    }

תשובת המרצה:

הקטע תקין לחלוטין מבחינה פונקציונלית.
הוא בודק האם קובץ המקור [= הקובץ אותו צריך להעתיק] אכן קיים.
וכמו כן הוא בודק האם הרשאות הגישה לקובץ ׳מאפשרות׳ לתוכנית לקרוא ממנו.

מה בודקים: (1) שנקבע במפורש שהקטע תקין — זו מלכודת הפוכה, מי שממציא באג מפסיד את הניקוד; (2) שמוזכרת מוסכמת ההחזרה: open() מחזירה -1 בכישלון ו-FD אי-שלילי בהצלחה, ולכן == -1 היא הבדיקה הנכונה; (3) ששתי סיבות הכישלון נמנות — הקובץ אינו קיים (ENOENT) או אין הרשאת קריאה (EACCES). בונוס: הקטע גם עומד בדרישת המטלה כי הוא משתמש בקריאת המערכת open ולא ב-fopen.

במסגרת מטלת תכנות בקורס ״תכנות מערכות״, התבקשו הסטודנטים לפתח concurrent Echo server.

לפניך קטע קוד שכתבו סטודנטים כחלק מהפתרון.
עליך לקבוע האם הוא תקין פונקציונלית, ואם לא — עליך להסביר במדויק מהי השגיאה ומדוע היא מתרחשת. 

int main() {
    int server_fd, client_fd;
    struct sockaddr_in address;
    int opt = 1;
    int addrlen = sizeof(address);
    char buffer[BUFFER_SIZE];


    address.sin_family = AF_INET;
    address.sin_addr.s_addr = INADDR_ANY;
    address.sin_port = htons(PORT);

    if (bind(server_fd, (struct sockaddr *)&address, sizeof(address)) < 0) {
        perror("bind failed");
        exit(EXIT_FAILURE);
    }



    if ((server_fd = socket(AF_INET, SOCK_STREAM, 0)) < 0) {
        perror("socket failed");
        exit(EXIT_FAILURE);
    }

תשובת המרצה:

הקטע אינו תקין מבחינה פונקציונלית.
הקריאה ל-bind() מתבצעת לפני הקריאה ל-socket().
מה שאומר שערכו של המשתנה server_fd הוא ׳זבל׳.

מה בודקים: (1) שנקבע במפורש שהקטע אינו תקין; (2) שהשגיאה מזוהה במדויק — סדר הקריאות הפוך: bind() נקראת לפני socket(); (3) שההסבר מדוע נכון — server_fd הוא משתנה מקומי לא מאותחל, ערכו ׳זבל׳, ולכן bind תופעל על מספר חסר משמעות ותיכשל (EBADF). בונוס: ציון הסדר הנכון — socket → setsockopt → bind → listen → accept.

מה לומדים מהבחינה הזו

  1. סדר קריאות המערכת של השרת — בעל פה. socket → setsockopt → bind → listen → accept (ובצד הלקוח socket → inet_pton → connect). שאלה 4 כולה נופלת על הסדר הזה: קריאה ל-bind לפני socket משאירה את server_fd כמשתנה לא מאותחל — ׳זבל׳.
  2. דעו בדיוק מה כל שדה ב-Inode מחזיק — ומה לא. mode = סוג הקובץ + הרשאות R/W/X; המיקום הפיזי ב-i_block/Extents; ושם הקובץ אינו ב-Inode כלל אלא ב-Directory Entry.
  3. מוסכמת ה--1. כל קריאת מערכת שנכשלת מחזירה -1; הסיבה מגיעה דרך errno. השמות הסמליים מ-<errno.h>, אבל המספרים הממשיים מכותרי הליבה — בדיוק שאלה 8.
  4. בשאלת ׳האם הקוד תקין׳ — לפעמים התשובה היא ׳כן׳. אל תמציאו באג. אם הקוד תקין, המענה הנדרש הוא להסביר מה הבדיקה עושה (בשאלה 3: קיום הקובץ + הרשאות הגישה).
  5. בעלות היא מושג נבחן. רק החוט שביצע lock רשאי לבצע unlock על אותו מנעול; מצב Ready או היות החוט main אינם מקנים שום זכות.
  6. אל תפסלו ׳אף אחת מהתשובות הנ״ל׳. היא הופיעה פעמיים (6, 12) והייתה נכונה באחת מהן. בדקו כל אפשרות לגופה, ורק אז החליטו.
  7. הפרידו בין מונחים שקל לבלבל: PID מול UID/GID; Data Block מול רשומת Inode; NVM (הדיסק) מול MM (הזיכרון); glibc מול הקרנל מול bash.
  8. ענו קצר ומדויק. תשובות המרצה עצמו הן 2–3 שורות שמכילות את המונחים המדויקים. שורה אחת עם המונח הנכון שווה יותר מפסקה של מסביב-לעניין — וגם חוסכת זמן: 14 שאלות ב-150 דקות.
